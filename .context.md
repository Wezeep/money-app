## Project Overview

**Wezeep** is a comprehensive money transfer and financial services mobile application with the following core features:

### Core Features
- **P2P Transfers**: Send money to other Wezeep users domestically
- **International Transfers**: Send money worldwide with currency conversion
- **Bill Payments**: Pay utilities, telecom, and other bills
- **Bill Splitting**: Split bills among multiple users
- **Money Requests**: Request money from contacts (single or batch)
- **Rewards System**: Cashback offers and referral rewards
- **Multi-Currency Wallets**: Support for USD, EUR, GBP, and local currencies
- **Contact Management**: Link and manage payment contacts

### Target Users
- Individual consumers sending money domestically and internationally
- Users who need to pay bills and split expenses
- Mobile-first users expecting modern UX

### Business Context
- Multi-currency support with real-time exchange rates
- Transaction fee structure (varies by type)
- Compliance requirements for international transfers
- Reward/referral incentive programs

## Architecture

### High-Level Architecture

```
┌─────────────────┐         ┌─────────────────┐
│   Mobile App    │────────▶│  Backend API    │
│  (React Native) │  REST   │  (Spring Boot)  │
│     + Expo      │         │    + H2 DB      │
└─────────────────┘         └─────────────────┘

─────────────────┐         ┌─────────────────┐
│   Mobile App    │────────▶│  Backend API    │
│  (React Native) │  REST   │  (Spring Boot)  │
│     + Expo      │         │    + POSTGRES   │
└─────────────────┘         └─────────────────┘
```

### Backend Architecture (Spring Boot)

**Pattern**: Feature-based modular architecture

```
backend/
├── domain/           # Domain models and repositories
│   ├── model/       # JPA entities
│   └── repository/  # Spring Data JPA repositories
├── feature/         # Feature modules (new structure)
│   ├── billpayment/
│   ├── contact/
│   ├── moneytransfer/
│   ├── request/
│   ├── reward/
│   ├── split/
│   ├── transaction/
│   └── wallet/
├── security/        # JWT authentication & authorization
├── config/          # Application configuration
└── api/             # Legacy controllers (being migrated)
```

**Key Decisions**:
- **Feature modules**: Each feature is self-contained with its own DTOs, services, and controllers
- **Domain models**: Shared across features via `domain/` package
- **JWT Security**: Token-based authentication with role-based access
- **H2 Database**: In-memory for development, easily switchable to PostgreSQL for production

### Mobile Architecture (React Native + Expo)

**Pattern**: Feature-based component architecture

```
mobile/
├── app/                    # Expo Router screens
│   ├── (tabs)/            # Tab navigation screens
│   └── [feature]-*.tsx    # Feature flow screens
├── src/
│   ├── features/          # Feature modules
│   │   ├── bill-payment/
│   │   ├── money-transfer/
│   │   ├── request/
│   │   ├── rewards/
│   │   ├── settings/
│   │   └── wallet/
│   └── types.ts           # Shared TypeScript types
├── components/            # Shared components & contexts
│   ├── AuthContext.tsx
│   ├── BillPaymentContext.tsx
│   ├── RequestContext.tsx
│   └── ThemeProvider.tsx
└── lib/
    └── api.ts            # API client
```

**Key Decisions**:
- **Expo Router**: File-based routing
- **Context API**: State management for flows and auth
- **NativeWind**: Tailwind CSS for React Native styling
- **Feature modules**: Reusable components exported via index.ts

## Development Conventions

### Backend Conventions

#### Naming
- **Controllers**: `[Feature]Controller.java` - `@RestController`
- **Services**: `[Feature]Service.java` - `@Service`
- **Entities**: `[Entity].java` - JPA entities in `domain/model/`
- **Repositories**: `[Entity]Repository.java` - extends `JpaRepository`
- **DTOs**: Records using `[Feature]Request/Response` pattern
- **Endpoints**: RESTful - `/api/[resource-plural]`

#### Code Style
- Use **Lombok** annotations: `@Data`, `@Builder`, `@RequiredArgsConstructor`
- Use **Java Records** for immutable DTOs
- **Constructor injection** (via Lombok `@RequiredArgsConstructor`)
- **Slf4j logging**: `@Slf4j` annotation
- Package-private by default, public only when needed

#### API Design
- REST endpoints follow: `/api/[resource]/[action]`
- Request/Response DTOs for all endpoints
- Return appropriate HTTP status codes
- Use `ResponseEntity<>` for flexible responses
- Exception handling via `@ControllerAdvice`

#### Security
- All endpoints require JWT authentication (except `/api/auth/**`)
- Use `@PreAuthorize` for role-based access
- Password encoding with BCrypt
- CORS enabled for mobile app

### Mobile Conventions

#### Naming
- **Screens**: PascalCase - `SendP2P.tsx`, `PayBillStatus.tsx`
- **Components**: PascalCase - `ThemeToggle.tsx`
- **Contexts**: PascalCase with "Context" suffix - `AuthContext.tsx`
- **API functions**: camelCase - `sendMoney()`, `fetchTransactions()`
- **Types**: PascalCase - `Transaction`, `User`

#### Code Style
- **TypeScript**: Strict mode enabled
- **Functional components** with hooks
- **Named exports** for components
- **Default exports** for screens
- Use `const` for components and functions
- Destructure props in function parameters

#### UI/UX Patterns
- **SafeAreaView** for all screens
- **ScrollView** for scrollable content
- **LinearGradient** for branded elements
- **Lucide icons** for consistency
- **NativeWind** (Tailwind) for styling
- Responsive text sizes: `text-sm`, `text-lg`, `text-3xl`
- Consistent color scheme: Purple/blue gradients

#### State Management
- **Context API** for global state (auth, theme)
- **Local state** (useState) for component-specific data
- **Context providers** for feature flows (BillPaymentContext, RequestContext)
- **Navigation state** passed via Expo Router params

#### Navigation
- **File-based routing** via Expo Router
- **Tabs**: `app/(tabs)/` - bottom navigation
- **Flows**: `app/[feature]-[step].tsx` - multi-step processes
- **Navigation**: `useRouter()` hook - `router.push()`, `router.back()`

## Key Patterns

### Backend Patterns

#### 1. Feature Module Pattern
Each business capability is a self-contained module:
```java
feature/moneytransfer/
├── dto/SendP2PRequest.java
├── dto/TransferResponse.java
├── MoneyTransferService.java
└── MoneyTransferController.java
```

#### 2. DTO Pattern (Request/Response)
```java
// Request
public record SendP2PRequest(
    String fromWezeepId,
    String toWezeepId,
    BigDecimal amount,
    String currency
) { }

// Response  
public record TransferResponse(
    Long transactionId,
    String status,
    BigDecimal amount
) { }
```

#### 3. Service Layer Pattern
Business logic isolated in services:
```java
@Service
@RequiredArgsConstructor
public class MoneyTransferService {
    private final TransactionRepository transactionRepository;
    private final WalletRepository walletRepository;
    
    @Transactional
    public TransferResponse sendMoney(SendP2PRequest request) {
        // Business logic here
    }
}
```

#### 4. Repository Pattern
Spring Data JPA for data access:
```java
public interface TransactionRepository extends JpaRepository<Transaction, Long> {
    List<Transaction> findByUserIdOrderByCreatedAtDesc(Long userId);
}
```

### Mobile Patterns

#### 1. Context Provider Pattern
State management for features:
```typescript
export const RequestProvider = ({ children }) => {
  const [selectedContacts, setSelectedContacts] = useState<Contact[]>([]);
  const [amount, setAmount] = useState("");
  
  return (
    <RequestContext.Provider value={{ selectedContacts, setSelectedContacts, amount, setAmount }}>
      {children}
    </RequestContext.Provider>
  );
};
```

#### 2. Multi-Step Flow Pattern
Navigation through related screens:
```
request-money.tsx (select contacts)
  → request-money-details.tsx (enter amount)
    → request-money-status.tsx (confirmation)
```

#### 3. API Client Pattern
Centralized API calls:
```typescript
// lib/api.ts
export const sendMoney = async (request: SendP2PRequest) => {
  const response = await fetch(`${API_URL}/api/transactions/send-p2p`, {
    method: 'POST',
    headers: { 'Authorization': `Bearer ${token}`, ... },
    body: JSON.stringify(request)
  });
  return response.json();
};
```

#### 4. Status Screen Pattern
Consistent success/error feedback:
```typescript
// Success with animation
<Check size={80} color="#10b981" />
<Text>Transfer successful!</Text>

// Navigate to home
setTimeout(() => router.push('/(tabs)/home'), 2000);
```

## Development Workflow

### Initial Setup

1. **Clone repository**
   ```bash
   git clone https://github.com/Wezeep/money-app.git
   cd money-app
   ```

2. **Set up credentials** (see [ONBOARDING.md](ONBOARDING.md))
   - Contact repo owner for `SEED_DATA_CREDENTIALS.md`
   - Or copy template and fill in password

3. **Install dependencies**
   ```bash
   # Mobile
   cd mobile && npm install
   
   # Backend (Maven wrapper included)
   cd ../backend
   ```

4. **Start development**
   ```bash
   # From root
   npm run dev        # Unix/Mac/Linux
   npm run dev:win    # Windows
   ```

### Daily Development

1. **Pull latest changes**
   ```bash
   git pull origin main
   ```

2. **Start backend** (port 8082)
   ```bash
   cd backend
   ./mvnw spring-boot:run
   ```

3. **Start mobile** (Expo dev server)
   ```bash
   cd mobile
   npx expo start
   ```

4. **Access H2 Console** (optional)
   - URL: http://localhost:8082/h2-console
   - JDBC URL: `jdbc:h2:mem:wezeep;DB_CLOSE_DELAY=-1;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE;DEFAULT_NULL_ORDERING=HIGH`
   - Username: `sa`
   - Password: (blank)

## Common Tasks

### Adding a New Feature (Backend)

1. **Create feature package**
   ```
   backend/src/main/java/com/wezeep/feature/[feature]/
   ```

2. **Create DTOs**
   ```java
   public record CreateFeatureRequest(...) { }
   public record FeatureResponse(...) { }
   ```

3. **Create Service**
   ```java
   @Service
   @RequiredArgsConstructor
   public class FeatureService { ... }
   ```

4. **Create Controller**
   ```java
   @RestController
   @RequestMapping("/api/[features]")
   public class FeatureController { ... }
   ```

5. **Add domain model** (if needed)
   ```java
   // In domain/model/
   @Entity
   public class FeatureEntity { ... }
   ```

6. **Create repository** (if needed)
   ```java
   // In domain/repository/
   public interface FeatureRepository extends JpaRepository<FeatureEntity, Long> { }
   ```

### Adding a New Feature (Mobile)

1. **Create feature module**
   ```
   mobile/src/features/[feature]/
   ```

2. **Create components**
   ```typescript
   // FeatureScreen.tsx
   export default function FeatureScreen() { ... }
   ```

3. **Export from index.ts**
   ```typescript
   export { default as FeatureScreen } from './FeatureScreen';
   ```

4. **Create screen in app/**
   ```typescript
   // app/feature.tsx
   import { FeatureScreen } from '@/src/features/feature';
   export default FeatureScreen;
   ```

5. **Add navigation** (if needed)
   ```typescript
   router.push('/feature');
   ```

### Adding a New API Endpoint

1. **Define DTOs** in feature module
2. **Implement service method**
3. **Add controller endpoint**
   ```java
   @PostMapping("/action")
   public ResponseEntity<ActionResponse> performAction(@RequestBody ActionRequest request) {
       return ResponseEntity.ok(service.performAction(request));
   }
   ```
4. **Add to mobile API client**
   ```typescript
   export const performAction = async (request: ActionRequest) => {
       return fetch(`${API_URL}/api/resource/action`, {...});
   };
   ```

### Updating Database Schema

1. **Modify entity** in `domain/model/`
2. **Restart backend** (H2 auto-recreates schema in dev)
3. **Update seed data** in `DataSeeder.java` if needed
4. For production: Create Flyway/Liquibase migration

## Troubleshooting

### Backend Issues

**Port 8082 already in use**
```bash
# Find process
lsof -i :8082  # Mac/Linux
netstat -ano | findstr :8082  # Windows

# Kill process or change port in application.yml
```

**Build fails**
```bash
# Clean and rebuild
./mvnw clean install

# Skip tests
./mvnw clean install -DskipTests
```

**H2 Console not accessible**
- Check `application-dev.yml`: `spring.h2.console.enabled=true`
- URL: http://localhost:8082/h2-console
- Verify JDBC URL matches configuration

### Mobile Issues

**Red lines in TypeScript files**
1. Restart TypeScript server: `Ctrl+Shift+P` → "TypeScript: Restart TS Server"
2. Reload VS Code window
3. Check `tsconfig.json` configuration
4. Ensure `node_modules` exists: `npm install`

**Expo not starting**
```bash
# Clear cache
npx expo start -c

# Reinstall dependencies
rm -rf node_modules package-lock.json
npm install
```

**Can't connect to backend**
- Check backend is running on port 8082
- Update `API_URL` in `mobile/lib/api.ts`
- Check network permissions
- For Android emulator: use `10.0.2.2:8082`
- For iOS simulator: use `localhost:8082`

**Module not found errors**
```bash
# Clear Metro bundler cache
npx expo start -c

# Check imports use correct path aliases
# @/components, @/lib, etc.
```

### Common Git Issues

**Accidentally committed credentials**
```bash
# Remove from index
git rm --cached SEED_DATA_CREDENTIALS.md

# Ensure .gitignore is updated
echo "SEED_DATA_CREDENTIALS.md" >> .gitignore
git add .gitignore
git commit -m "chore: Add credentials to gitignore"
```

**Merge conflicts**
```bash
# Accept theirs
git checkout --theirs <file>

# Accept yours
git checkout --ours <file>

# Manual resolution
# Edit file, then:
git add <file>
git commit
```

## Project-Specific Context for AI Assistants

### Architecture Migrations in Progress

**Backend**: Migrating from flat `api/` structure to feature-based modules
- **Old**: `api/controller/`, `api/dto/`, `service/`
- **New**: `feature/[feature]/` with co-located DTOs, services, controllers

- Moved from `src/screens/` to `src/features/` + Expo Router `app/`

### Key Design Decisions

1. **H2 in Dev, PostgreSQL in Prod**: Easy local development, production-ready database
2. **JWT for Auth**: Stateless, mobile-friendly authentication
3. **Expo over vanilla React Native**: Faster development, better tooling
4. **Feature modules**: Better code organization, clear boundaries
5. **Context API over Redux**: Simpler state management, good enough for app scale

### Common Code Locations

- **User authentication**: `backend/security/`, `mobile/components/AuthContext.tsx`
- **Transaction logic**: `backend/feature/moneytransfer/`, `backend/domain/model/Transaction.java`
- **Wallet operations**: `backend/feature/wallet/`, `backend/domain/model/Wallet.java`
- **API client**: `mobile/lib/api.ts`
- **Shared types**: `mobile/src/types.ts`
- **Theme**: `mobile/components/ThemeProvider.tsx`, `mobile/theme.ts`
